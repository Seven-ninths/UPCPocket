# Web 地图、交互与设备定位

以 UPC Pocket 2.1.0 开发线提交 **049a320** 的现场源码为基准。本节给出可直接实现的 Web UI 行为。C++ 侧接管地点域模型、路线计算与引导状态时，Web 仍负责浏览器权限、传感器、地图绘制和人与页面的交互。Android 现有实现使用 WGS84 [经度, 纬度]。Web 若更换绘图库或使用 Wasm，继续使用同一坐标约定和同一数据快照。

## 地图入口和地点交接

- 「服务 → 校园地图」和首页固定卡都打开二级地图页。Android 入口和路由 ID 均为 `campusmap.home`，服务分类 `CAMPUS`，排序值 4。普通打开按常用校区初始化。古镇口偏好映射到 `gzk`，唐岛湾偏好和「全部」映射到 `tdw`。读取偏好遇到 I/O 错误也用 `tdw`。切换地图校区只影响该页会话。
- 课表和首页今日课程的详情页，有可交接地点文字且地图插件可用时显示「在校园地图查看」。宿主只交符合条件的地点文字，前后裁空白并截到 160 个 Kotlin UTF-16 代码单元。地图跨校区解析地点后，精确匹配则切到该校区、选中目的地和居中。无法解析保留提示「未能定位课表地点，请选择校区并搜索楼名」，随后可手动搜索。跨产品移植用本机内存传递，页面 URL、历史记录和日志只保存非个人的站点路由。
- 校园通讯录的「导航」通过宿主交 `{ campus, placeId }`。地图切到指定校区，只接受 ID 正好相同、坐标存在、可信位置类型为 `osm / verified / verified-area` 且非楼门的地点。无匹配时仍显示该校区并提示「未能定位该地点，请搜索楼名」。用 ID 查找，不按显示名、其他校区 ID 或近似位置替换。同楼机构的稳定 ID 可独立显示，其路线仍可共用楼门。
- 两种交接封装为 `TimetableText` / `Exact`。Android 实现用原子引用覆盖上一请求，地图路由进入时一次性取走。Web 嵌回宿主时用同样的一次性交接。独立 Web 页可提供同样的两种宿主调用入口导入公开或脱敏示例。地图插件停用时不显示地图入口；学校通讯录仍可查地址，课表仍可看原始地点。

### 搜索和课表匹配

普通搜索只在当前校区内进行。按 Kotlin `lowercase()` 做 Unicode 小写，去 Unicode 空白和 `·()（）-`。将地点显示名、`kind` 字符串、`region`、每个别名都独立归一化。依次按显示名全等 0 分、任意键全等 1 分、任意键前缀 2 分、任意键包含 3 分排列，同分保留资产记录顺序。空输入无搜索结果。UI 排除 `kind=entrance`，保留同楼服务和待核地点；待核地点可以看详情，缺有效路线目标则「查看路线」不可用。点击地图或结果列表均使用地点稳定 ID 进入同一个选点动作。

课表文字需先 NFKC，再按上面规则归一化。跨两校区构建非楼门候选，先比准确显示名，其次比长度至少 2 的全等别名，最后用显示名/别名做前缀，尾部须完整匹配 `[a-z]?[0-9]{2,5}(?:教室|机房|室)?`。房间号匹配按最长楼名前缀，只有唯一地点才接受。一字别名只在带合法房间号的情况下能进入匹配。如果直接没有命中，逐个移掉尾段 `（备注）`（NFKC 后是 ASCII 括号）。剩余表达式必须是唯一的已知数字房间，尾注中的校区/东区或西区/可解析的另一地点不得与匹配结果冲突。东营、科教园区或未知校区提示不默默忽略。不要将通用搜索的子串候选自动当作课表精确交接。

原有测试例子包含 `南教110` → 南教楼，`微601`、`微（６０１）教室`、`基础实验楼D601`、`微601（唐岛湾校区）` → 唐岛湾基础实验楼 D 区。`微报告厅`、`601`、`未名楼601（示例备注）`、`微601（古镇口校区）`、`微601（南教110）` 和跨校区重名 `微601` 都保持未解析。

## 页面组成与交互状态

使用安全区、手机键盘避让和窄屏弹性布局。由上到下为顶部栏、填满可用空间的地图、可滚动的底部面板。

| 区域 | 出现和操作 |
| --- | --- |
| 顶部 | 返回、标题「校园地图」、唐岛湾/古镇口两枚筛选。地图加载成功且非引导时可切换，清空当前搜索、起点、目的地、路线和跟随，保留方式和最近定位。搜索框位于下一行，引导时隐藏。进入手选起点时搜索提示换成「搜索起点，或在地图上点选」。返回优先关闭手选起点或当前聚焦的非空搜索，否则返回宿主。 |
| 地图 | 点地点、点候选线、拖动与双指缩放、双击放大，右上指南针、右下放大/缩小/定位、左下 OSM 署名。拖动和缩放后退出镜头跟随，再点定位恢复。定位状态放地图左上角，搜索列表打开时隐藏。地图加载失败后有「重新加载」。 |
| 搜索结果 | 非引导且手选起点或输入非空时，地图上方显示列表。空查询且手选起点显示「在地图上点选起点，或输入楼名搜索」，无匹配显示「当前校区未找到匹配地点」。一般结果展示地点名、区域、类型及核实状态。选中后关闭键盘、清查询、取消选择起点模式、关闭镜头跟随并居中。 |
| 底部常态 | 未选终点提示从地图或搜索选择。已选则显示目的地名、地点核实说明、同楼服务切换、起点及「换起点」，手选时出现「用定位」。步行和普通自行车切换。手选起点不等定位即可「查看路线」。使用当前位置时可取消等待精确定位。计算进行中按钮禁用。 |
| 底部预览 | 预览成功显示可横向滚动的候选卡，第一项为「最快」，其余「路线 2」「路线 3」。卡片有时长、距离及选择状态，地图线与卡片同选。显示目的地/入楼说明与「开始导航」。没有可用路线时仍可换点或模式，重新规划。 |
| 底部引导 | 显示「前方 N 米」与动作、剩余距离和预计时长。等待定位、重算或失败时显示状态文本，不显示过时转向。引导期间不允许用地图点地点或线路切走。实时无路时，仅有精确且在当前校区的定位，才启用「重试规划」。到达显示简要结果及「完成」，引导中显示「结束导航」。 |

Android 适配阈值是可用高度低于 480 dp 使用紧凑布局。搜索覆盖层上限紧凑 132 / 常规 213 dp。底栏占可用高度上限紧凑 42% / 常规 46%，上角 21 dp，内间距横 18 / 纵 12 dp，行距 8 dp。搜索覆盖非空时底栏隐藏，只有「手选起点且查询为空」的引导条可与底栏并存。Web 采用 CSS px 对应视觉单位，DPR 只用于 Canvas 画布分辨率。

地点类型标签包括餐厅、校门、校园地标、图书馆、校医院、公寓、生活服务、体育场地和教学楼。核实状态 `estimated / reference / verified / verified-area / verified-building / surveyed` 对应位置待核、楼栋参考地点待核、位置已核实、区域已核实、所在楼栋已核实、用户标注；其他类型显示「地图已标注」。不足 1,000 m 的距离取整为米，其余用一位小数公里。时长按 `max(1, ceil(seconds/60))` 显示分钟。「前方」提示只在转向距离至少 1 m 时展示。

到达状态保留底部结果卡和「完成」操作。此时引导不再占用地图，恢复搜索和校区切换，并采用普通地图绘制和命中规则。

## 地图画布

### 坐标和镜头

设地图边界 `[west,south,east,north]`，地图始终北向上。投影使用每度纬向 111195 米，东西系数 `E = 111195 × cos(rad((north+south)/2))`。地点的世界坐标为 `x = (lon-west) × E`、`y = (north-lat) × 111195`，世界尺寸 `extent = [(east-west) × E, (north-south) × 111195]`。这里的投影是画布近似，把世界坐标与路线进度的地理距离分开计算。绘制建议分底图、路线和标记、实时位置三层。

默认镜头中心 `extent/2`，缩放 `zoom=1`。`middle=(画布宽/2, 高/2)`，`fitScale = max(min(画布宽/extent.x, 画布高/extent.y), 0.001) × 0.92`，`scale = fitScale × zoom`，`origin = middle − center × scale`，在这个视口内 `screen = origin + world × scale`。

- 允许缩放 0.85–18 倍，按钮每次乘 1.5 或除以 1.5；双击锚点乘 1.55。手势按指尖中心计算 `worldAtAnchor=(anchor−oldOrigin)/oldScale`，新镜头中心 `worldAtAnchor−(anchor+pan−middle)/(newZoom×fitScale)`。连续手势后在每轴把中心限制到该轴世界尺寸的 −25%–125%。
- 选地点使用 `mapDestination` 的显示位置居中，至少 2.5 倍。该显示位置优先首个已接路楼门，再到该地点直属的已记录楼门，末位回地点自身；正式路线可选其他入口，预览标记不能替代算路目标。
- 预览时选路线变更或画布尺寸变更，镜头居中到该线世界包围盒。目标尺度 `min(0.77×画布宽/max(路线宽,34m), 0.72×画布高/max(路线高,34m))` 除以 `fitScale` 得缩放，限制 0.85–9。用户镜头跟随启用或正在引导时，不为候选线强制适配。
- 跟随时定位在绘图边界内才移动镜头。引导缩放至少 4，单纯定位至少 1.7；保留更高的现有比例。地图北向上，跟随不旋转。

### 图层和命中

绘制顺序从底到顶为 `water → area → field → path → road → building`，面 `water / area / field / building` 闭合填充。道路描边 4.5 dp、内线 3 dp，步道 1.35 dp，建筑边线 0.55 dp。道路和步道端点圆角。候选辅助线宽 4 dp。主路线用 9 dp 浅色/深色外围加 6 dp 主色内线；已取得进度后，全线底层宽 6 dp、主色 alpha 0.28，剩余线使用正常主路线颜色覆盖，从 accepted progress 所在边的 fraction 插值起绘。待规划或弱定位期间的旧路线由控制器状态保留，别从当前 GPS 直接裁掉已走路径。

- 普通标记只绘制有坐标、无 `parentId`、非 `entrance` 的地点。选中地点或同楼子地点时避开相应宿主普通点，在地图目的地绘制终点标记。已核或 `surveyed` 为实心，其余用底色填充、对应颜色做 1 dp 描边。缩放小于 2.5 时半径 3.2 dp，其余 4.2 dp。目的地用 10/6.5 dp 外/内圆。未开始截线路径时，路线首点或手选起点显示 9/5.5 dp 起点，之后不重复显示旧起点。
- 地图文字先画选中目的地，12 sp 半粗；其他 10 sp 中字，先放点上方，距顶部不够则放下方，水平方向夹到画布。背景留 3 dp 边缘、5 dp 圆角，碰撞或超过底边跳过。倍率 <4 时只显示 `south, library, new-library, sport, north-gate, south-gate, engineering, teach, learning, west-food, ling, east-sport` 集合中的可见点，候选最多 14。≥4 倍取可见点候选最多 44。继承资产顺序，标签碰撞后实际可见数会更少。
- 点击命中先找半径 23 dp 内离手指最近的地点，当前选中宿主排名奖励 2 dp。若其真实距离 <13 dp，优先选地点。否则找距所有路线线段最近的线，小于等于 13 dp 命中路线；无路线命中再回退最近地点。线段距离在屏幕上做点投影并夹在两端。引导期间忽略这些点击，继续支持拖动、缩放和返回定位。
- 导航引导状态隐藏普通 POI 和候选线。位置在绘图边界内才画箭头或圆点。定位误差盘半径为误差米数 × 视口像素/米，alpha 0.12，半径最多画布较大边的 3 倍。外圆半径 10 dp；缺航向内圆 7 dp。有航向时用向上的箭头顺时针旋转。行进首先使用可信定位航向、其次设备朝向。普通浏览相反。
- 右上 `北` 指南针窗口距上/右 12 dp，左下地图署名可点击 `https://www.openstreetmap.org/copyright`，显示 `© OpenStreetMap contributors`。离线运行时继续展示文字署名。

## 定位与前台生命周期

现行 Android 逻辑不在打开地图时自动申请定位。用户点「定位」「用定位」「查看路线（当前位置）」或「开始导航」才申请。一般「定位」可以接受大致位置以绘制位置范围；路线规划和引导需要可信的精确位置。拒绝或停用定位仍可手选起点预览，浏览器端要可访问地表达权限拒绝、传感器缺失和没拿到定位的不同状态。

Android 源只在页面和 Activity 处于 RESUMED 且定位启用时订阅。一次同时登记允许的 GPS / network / fused providers，大致权限时不登记 GPS。更新间隔和状态检查 1 s，部分 provider 登记失败时每 5 s 只重试缺失的，首个已注册 provider 启动后 10 s 没合格显示位置进入 `NO_FIX`。位置状态 `OFF / WAITING / NO_FIX / ACCURATE / LOW_ACCURACY / APPROXIMATE / DISABLED / UNAVAILABLE / DENIED`。退出引导、到达或离开可见页面后取消订阅。切校区时不强制关闭已打开的定位，进入非 active 页面时停止传感器。后台清除当前定位，回到页面再获取。

接受坐标必须有效且误差有限大于零，经纬度分别在合法范围。以单调时间估算数据年龄，0–15 s 内可供平台显示。候选选取为最新时间、同时间选误差最小。如果较新的误差比前一条可导航的误差大至少 8 m，前条还不到或等于 4 s，短暂维持前条；否则显示最新候选。引导可信阈值是设备明确精确定位且误差 `0 < accuracy <= 30 m`、年龄 0–15 s。Android 控制器还有单独的 30 s 展示输入兜底；Android 平台的正常采集已经在 15 s 失效。设备航向仅在真有速度且不低于 1 m/s、航向与误差有效、设备报告航向误差 0–35° 时交给地图匹配。位置层会按上条规则使用设备指南针补充绘制，指南针朝向不作为移动方向参与算路。

位置采集和导航控制器各自有生命周期。用当前位置查看路线时，UI 应可等待可信 fix，也可取消等待或手选起点。点击开始如果没有可信 fix，保持等待并自动开始，不要求用户重复点；手选路线开始时应从实测位置检查并更新。中途失败、偏航、到达由控制器统一处理，视图从状态派生。Web 的事件来源可以是浏览器位置、人工点选或测试注入。测试注入位置只作验收，正式展示不得冒充真机。

### 指南针

Android 优先 `TYPE_ROTATION_VECTOR`，再用 `TYPE_GEOMAGNETIC_ROTATION_VECTOR`。只在地图页激活且 RESUMED 时订阅。读取不超过 10 Hz，绝对读数年龄须 0–2 s，传感器精度至少 MEDIUM，已给出的误差上限 35°。屏幕旋转 0/90/180/270 时分别按坐标轴 `X,Y / Y,−X / −X,−Y / −Y,X` 重映射，改变屏幕旋转时清除历史。屏幕上缘投影在水平面的平方模 `east²+north² < 0.04` 时视为不稳定。由地图边界中心、海拔 0 和当前时间计算磁偏角，再将真北角归一化为 `normalize(magnetic+declination)`。

最短转角 `normalize(next-prev+180)-180`，按 α=0.35 做环形平滑。如果新平滑角与已发布值相差小于 0.75° 不发布；首次直接发布。每秒检查一次过期或旋转改变，距最后有效传感器读数超过 2 s 清空。具有真北角 `azimuth` 时指南针图标逆时针旋转 `-azimuth`；设备位置箭头顺时针旋转，底图保持北朝上。设备方向不可用时显示静态「北」和无动态方向的可访问标签。读数类型不清楚时不要把磁北、真北或行进 bearing 混用。

## 浏览器移植约定

- 建议用静态 Canvas 2D + CSS 面板，不要求地图 SDK、在线瓦片或账号。浏览器地理定位用 HTTPS 或本地可信环境的 `navigator.geolocation.watchPosition`。以用户主动操作为入口，绑定页面可见性和退出状态。隐藏页面暂停/释放位置和方向订阅，重回可见状态后等新 fix。浏览器提供的精度属性为米，但平台未必暴露 Android 的精确/模糊权限类型，不能假定收到即为精确。可据已验证目标设备的精度和新鲜度决定是否开始实时引导，否则保留手动预览。
- 浏览器时间戳与 `performance.now()` 可能不是同一时间域。入队前把 fix 的年龄换到本会话单调时间轴，再交给控制器。Geolocation 的 `heading` 只有在有可信移动速度和有效航向时进入实时匹配。浏览器未提供原版所需航向误差时，优先把 `bearing` 设为空以保持原版「可信航向才参与」的规则。指南针用目标浏览器提供的方向事件和屏幕旋转校正，真北来源未验证则保留静态「北」。传感器能力和权限在实现后做目标真机验收。
- 浏览器本机的 JS/C++ Wasm 状态应只在内存处理定位、路线进度和可能来自个人课表的地点文字。若选 C++ 本机进程 + Web 界面，让引擎在同一设备本地通信；把位置发公网会改变 Android 现有隐私边界。包内公开静态地图资产可以缓存。引擎放 Worker 或其他非 UI 线程，按算路请求代次丢弃迟到结果。UI 应先响应换点/换校区，再等待新路线。
- 桌面浏览器没有定位或朝向权限时仍能浏览地图、按名或别名搜索、选双端、预览步行/骑行路线。用断网和双路线等普通场景验证可用性，再用真实步行/骑行分别验收定位、转向、自动改线和到达。静态导入测试不要把现场路况、楼门开放或网页传感器兼容当作已验证。
