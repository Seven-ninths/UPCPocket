# UPC Pocket 校园导航 C++ / Web 复现交接

**目标**　用同一份校园数据，在浏览器复现 UPC Pocket 的离线地图、地点检索、步行与骑行路线和前台实时引导。C++ 负责数据、算路和引导，Web 负责界面、设备权限与传感器。

**基准**　UPC Pocket 2.1.0 开发线，完整提交 `049a32064f6368d14b602590c57be3df0057f7e3`。此源码树与合入校园通讯录后的上游提交 `45855f3ae9dc5e174064fca7237d08f961821dfe` 一致。先对齐冻结快照，之后的地图修订应另换数据版本和回归样例。

**交付目标**　一个可在 Windows/Linux 执行的 C++ 测试程序，一个可静态部署的浏览器入口，以及一份区分算法对照、浏览器测试和校园现场走测的结果。实现方以本页的验收项为任务清单，每个阶段完成后记录实际通过的检查。

## 从哪里开始

1. 先读[数据与授权](data.md)，核对[生产地图、节点和边数据](../../../feature/campusmap/src/main/assets/campus_map.json)的完整性。直接使用资产附带的公开坐标，保留数组顺序。
2. 读[算路与导航规格](route.md)，用[基准结果 JSON](fixtures.json)逐项对照。需要确认边界条件时，按规格中的函数名查看[原导航源码和测试](../../../feature/campusmap/)。
3. 读[地图 UI 与浏览器适配](ui.md)，实现原版画布、搜索和前台导航交互。课表文字和通讯录地点 ID 交接通过两个不同的宿主方法完成。
4. 对照原版的[模块说明](../../../ARCHITECTURE.md)、[宿主接口](../../../API.md)、[入口映射](../../m5/README.md)、[隐私说明](../../PRIVACY.md#校园地图与前台定位)和[数据决策](../../adr/007-offline-campus-navigation.md)。[旧开发计划与验证记录](../2026-11-19-campus-navigation-implementation.md)保留当时的路线结果，本交接包的冻结数据以 `fixtures.json` 为准。

## 功能范围

| 能力 | 用户可见行为 |
| --- | --- |
| 地图入口 | 服务目录打开地图，可固定首页。按常用校区打开，全部校区默认唐岛湾。进入后可以切换唐岛湾与古镇口。 |
| 离线地图 | 显示两校区地物、建筑、场地、道路、地点和路线图层。地图北朝上，可拖动、缩放、复位和查看当前位置。 |
| 地点与楼门 | 按楼名、别名、类别、片区检索。可点图选地点，显示待核地点和标注楼门。有关联的同楼机构可使用主楼的接路入口。 |
| 其他功能直达 | 课表详情及首页今日课程传地点文字，进行楼栋匹配。校园通讯录传校区与地点 ID，精确选中有有效坐标的地址。 |
| 路线预览 | 手选起点或用当前定位，切换步行与骑行。地图和列表可选最多三条候选，显示距离和估时，默认最快。 |
| 实时引导 | 用最近的可信精确位置开始，显示当前位置、匹配进度、下个转向、剩余距离和时间。偏航确认后重算，到达后提示结束。 |
| 楼栋出发和到达 | 明确匹配的室内定位可使用已接路的楼外起点，提示走到室外。步行按入口路段到门，骑行可停在附近可骑道路并提示步行前往。 |
| 设备状态 | 处理缺定位、拒绝、模糊定位、精度差、过期、出校区、等待和重算失败。指南针只在页面前台使用，无法可靠判定时显示静态北向。 |

古镇口东区和西区共享校区选择，具有独立边界和不连续的路网。古镇口西区可浏览和搜索地点，主要楼间路线仍缺数据。当前实现的引导是校内、前台、文字式，复现范围以此为准。应用内各地点搜索和路线计算都使用随包数据。

## 建议的工程切分

这是移植实现的接口建议。原 Android 代码和数据规则见三份规格，C++ 工程可以按接收方目录习惯命名。

| 实现单元 | 输入、职责与输出 |
| --- | --- |
| `cpp/dataset` | 读取 UTF-8 V1 地图 JSON，建立 ID 到数组下标的索引。提供校区包含判断、建筑判断、检索和课表解析、目标门候选。 |
| `cpp/routing` | 输入校区、起点、出行方式和候选终点。输出失败枚举或最多三条候选，包含折线、距离、秒数、入口和室内起步标记。 |
| `cpp/navigation` | 输入 C++ 路线与标准化位置，维护状态、最近接受的时间、进度、偏航和到达计数。输出 UI 可直接展示的快照。 |
| `cpp/bridge` | 将同一核心作为本地 C++ 库使用，并以 WebAssembly 提供给 Web Worker。JS 传 UTF-8 数据并接收快照。原版的距离计算与图算法只维护一份。 |
| `web/worker` | 加载 Wasm 与随包 JSON，串行处理命令。请求带单调递增的代次，切校区、改点、改模式后丢弃旧结果，保证 UI 按新状态响应。 |
| `web/app` | 用 Canvas 2D 绘制地图、路径与标记，使用 HTML/CSS 面板、输入控件与键盘交互。管理权限、Geolocation、设备方向及页面可见性。 |
| `tests` | 用同一 JSON 用例检查原生 C++ 和 Wasm，另外用模拟定位序列测试 Web 页面与状态更新。 |

核心建议使用 C++20，地理坐标和计算使用 `double`。使用成熟 UTF-8 JSON 解析库。校区、地点 ID 和内部路网节点的字符串保持原样。课表匹配需 Unicode NFKC，Web 可以用 `String.prototype.normalize("NFKC")` 做平台适配；若匹配逻辑在 C++ 共用库内，使用支持 NFKC 的 Unicode 库，并用同一组中文用例验证。画布继续画自有面、线和坐标点，可不引入在线地图 SDK、地图密钥或地图服务。

### 核心边界与消息

将浏览器位置 `coords.longitude`、`coords.latitude` 转为 `[longitude, latitude]`，把年龄换算到一个会话单调时钟，距离用米、时长用秒、时间戳用毫秒。C++ 与 JS 都区分 null 和 0。首次加载在 Worker 初始化数据，主线程只负责文件加载错误与渲染。浏览器在 HTTPS 或本机可信环境获准使用定位，离开前台从 Web 侧停止监听。[Web 定位 API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition)

建议以 `{requestId, generation, operation, payload}` 请求和 `{requestId, generation, result}` 响应作为桥接格式。建议使用固定操作 `init`、`search`、`resolveCourse`、`dispatch`，其中 `dispatch` 接收以下 UI 事件并返回完整状态。可在 C++ 使用 `std::string` 返回 JSON，绑定给 Emscripten；若使用 C ABI，则提供配套释放函数，由同一 Wasm 模块管理内存。[Emscripten 的 C++ 与 JavaScript 互操作](https://emscripten.org/docs/porting/connecting_cpp_and_javascript/Interacting-with-code.html)

| 事件约定 | 输入 | 结果或副作用 |
| --- | --- | --- |
| `setCampus` | `{campusId}` | 重置当前路线和选点，保留行进方式与最新定位。 |
| `openCoursePlace` | `{locationText}` | 用课表规则匹配唯一地点。无结果或地点歧义时给手动搜索入口。 |
| `openDirectoryPlace` | `{campusId, placeId}` | 用指定校区和精确 ID 匹配，校验有可信点位。 |
| `choosePlace` | `{placeId, role: "start" / "destination"}` | 更新其中一端，清理旧路线。 |
| `useCurrentStart` | 空对象 | 清除手选起点。 |
| `setMode` | `{mode: "WALK" / "BIKE"}` | 按当前状态更新或重算。 |
| `plan`、`start`、`stop`、`retry` | 空对象 | 分别处理预览、开始、结束与重试。具体前置条件见[算路规格](route.md)。 |
| `selectRoute` | `{routeId}` | 仅在预览状态选择候选。ID 有效期是本次规划。 |
| `updateFix` | `{nowMs, fix}` | fix 为 `null` 或 `{point, accuracyMeters, sampledAtMs, precise, bearingDegrees}`。更新定位和导航状态。 |

导航状态快照至少包含校区、方式、手选起点、目的地、状态枚举、提示、路线、选中路线 ID、当前定位、进度、引导与错误详情。每条路线至少包含 `id`、`mode`、`points`、`meters`、`seconds`、可空入口 ID 和 `startFromEntrance`。如需展示已走/待走线段，直接由当前路线和 `routeProgressMeters` 找插值断点。使用双精度保留算法值，在展示端用原版规则换成米、公里、分钟。

## 移植顺序与验收

1. **加载数据并画静态地图。** 首先核对 [data.md](data.md) 中的两校区 ID、原始 JSON 大小、SHA-256、地物/地点/节点/边计数。点「古镇口」可见东、西两块区域，不把外包矩形中间的区域算作校内。
2. **实现检索和交接。** 用 `fixtures.json` 的 `searchCases` 与 `courseCases` 核对顺序、课表消歧和空匹配。另验证一个非入口点的目录 ID 精确选中、无坐标地点仍能被搜到，以及同名字跨校区不误选。
3. **实现路线和纯计算测试。** 逐一核对 `routeCases` 的失败枚举、候选数、顺序、折线点顺序、入口、ETA 和首条指引。按每段后续规格复刻单行、门口、室内起步、过近、折返路线测试。建议距离误差 ≤0.01 m，折线坐标单分量误差 ≤1e-7°，整数 ETA 与失败枚举完全一致。先跑原生 C++，再验证同一套测试在 Wasm 输出一致。
4. **完成浏览器交互。** 对齐服务入口、起终点搜索、选路线、缩放和拖动、定位图层、指南针读数不足时的回退、进度与引导。优先测试桌面和手机普通窗口。清断网后，应能使用已经加载的网页和数据查看地图和预览；若目标要求断网重新打开，再给所有文件加可验证的版本化缓存。
5. **验证跟随状态。** 用带单调时钟的注入样本复现等定位后继续、偏航防抖、保持原门优先、两次有效位置确认到达、后台暂停与回来等新定位。跟随中的重算保留原线并收起过期转向。从手选起点首次切入导航并重算时，清空原预览线，直到得到当前位置的新路线。用 [route.md](route.md) 的序列样例和原版 Controller 单测作为判据。
6. **在校园做走测。** 出发前核对楼门、通行方向和骑行限制。分别记录校区、方式、设备、选中入口、位置质量、偏航重算、到达和异常。古镇口西区使用可浏览、无路提示作为当前验收目标。

建议 CMake 项目将原生用例纳入 CTest。实现完成后可用 `cmake -S . -B build -DBUILD_TESTING=ON`、`cmake --build build`、`ctest --test-dir build --output-on-failure` 复验。Wasm 构建和网页启动命令写入接收方 README，并明确测试使用的浏览器和终端。

### 基准结果怎么用

`fixtures.json` 由此提交的 Kotlin 几何、解析、选点和算路代码在 JVM 上读取原始地图生成。仅以桌面读文件和 JSON 适配替换 Android 资产入口。每个预览用例都含实际起点、失败枚举或每条候选的距离、秒数、终点门 ID、室内起步标记、初始指令和完整折线。 `origin: "manual"` 按手选规则取第一个可用起点目标，`origin: "location"` 使用地点坐标模拟当前设备位置。这些点是资产中的公开地点。

| 示例 | 步行首选 | 骑行首选 | 候选数 |
| --- | ---: | ---: | ---: |
| 唐岛湾南门到图书馆 | 627.23 m / 465 s | 632.73 m / 176 s | 3 / 3 |
| 唐岛湾 17 号学生公寓到工科楼 E 座 | 892.60 m / 662 s | 965.52 m / 269 s | 3 / 3 |
| 唐岛湾南门到逸夫楼 | 184.79 m / 137 s | 171.10 m / 48 s | 2 / 1 |
| 古镇口东区综合教学楼到文体中心 | 484.18 m / 359 s | 484.18 m / 135 s | 3 / 3 |
| 古镇口西区珠山餐厅到学 8 | `NO_START_ROAD` | `NO_START_ROAD` | 0 / 0 |

这些是冻结数据和代码下的算法结果。当前交接验证范围包括地图资产完整性、JVM 参考结果、文件路径和归档完整性。新 C++/Web 实现、浏览器真机定位以及校园现场通行、楼门、偏航和到达仍需由接收方验收。
