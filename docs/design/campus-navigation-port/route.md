# 算路、定位匹配与导航状态

本节以原版 `CampusRouting.kt`、`CampusMapData.kt`、`CampusMapController.kt` 及 `CampusMapLocation.kt` 为准。C++ 侧可以把坐标几何、路由、路线匹配与引导作为无 UI、无定位权限依赖的纯计算库，Web 侧负责选点、定位采样、状态呈现。下文使用原版的数值和判断顺序。

### 坐标与坐标几何

- 经纬度用 `double`，数组始终是 WGS84 `[lon, lat]`。校区用于算路的边界取 `areas` 多边形并集，`bounds` 是视口范围。
- `distance(a,b)` 以 `111195.0` 米每度近似。东向量等于 `(b.lon-a.lon)*111195*cos(rad((a.lat+b.lat)/2))`，北向量等于 `(b.lat-a.lat)*111195`，返回 `hypot(east,north)`。方位角按 `atan2(east,north)`，以正北为 0°、顺时针归一化到 `[0,360)`。
- 把点投影到边时，用边的平均纬度余弦缩放经度，在局部平面做向量点积，分数夹在 `[0,1]`。退化边的分数为 0。再按分数线性插值得到经纬度，重新用 `distance` 计算该点到垂足的距离。
- 多边形射线奇偶法先判断点距任意边是否在容差以内。校区边界容差 **0.7 m**，建筑轮廓 **0.05 m**。建筑只查 `geometry.kind == "building"`。

### 路由输入和点位解析

`CampusRouter::plan(from, targets, mode, startFromPlace)` 输入校区、起点、候选目标、行进方式及是否手选起点。输出一个失败枚举或 1–3 条路线。步行速度 **1.35 m/s**，普通骑行 **3.6 m/s**。每个候选目标有路网锚点和可空的楼门记录。

- `connectedEntrances` 通过 `parentId` 关联地点所在主楼。只用 `kind=entrance`、`confidence=surveyed` 且门坐标和接路坐标都在校区边界中的记录。唐岛湾还要求门在建筑外。同一楼的服务点共用主楼入口。
- `routeTargets` 优先返回这些入口的 `accessPoint` 与入口元数据。地点是未接路的入口时返回空，不作推断。普通地点若无接路入口，回到主楼或本身坐标，仅接受坐标非空且置信度为 `osm`、`verified` 或 `verified-area`。手选出发地使用第一个可用目标的锚点。
- 活动地图请求可精确指定 `campus + placeId`。精确请求只选该校区具有可落图坐标（osm、verified、verified-area）且非门的点。课表文本由 `resolveTimetablePlace` 跨校区匹配，先 NFKC、去首尾空白、小写，再去掉空白和 `·()（）-`。优先完整名称，再用长度至少为 2 的别名精确匹配。否则取与教室号正则 `[a-z]?[0-9]{2,5}(?:教室|机房|室)?` 匹配的最长地点前缀。若没有命中，可以去掉末尾一个或多个括号注释，再匹配此前缀规则。注释中的已知校区、东区或西区、可匹配地点须与结果一致，拒绝矛盾或含未知校区的注释。最终必须唯一，不从包含关系猜楼栋。
- 地图搜索不同于课表匹配。`search` 对名称、分类、区域及别名做小写和同一套去字符处理，排序为完整名称相同、任一键相同、前缀、包含，同级保留数据顺序。入口是否呈现由界面过滤。

### 路网构造和算法

1. 起点超校区边界返回 `OUTSIDE_CAMPUS`。未提供目标返回 `NO_END_ROAD`。已提供的目标经过校区边界筛选后全空时返回 `OUTSIDE_CAMPUS`。筛选 `walk` 或 `bike` 为真的有向边，保留输入顺序。为吸附和备用路线准备无向街段键 `(uint64(minIndex) << 32) | maxIndex`，同键边分组，旅行方向仍用各自有向边。
2. 在允许模式的街段组中线性扫描垂足，选距离限制内的最近一点。距离相等保留首项。实时起点 **50 m**，手选起点 **65 m**。实时起点吸附失败才尝试唐岛湾楼内特例。起点须落在唯一建筑轮廓中，该轮廓内须恰有一个有效的顶层地点，其已测楼门必须有建筑外接路锚点。每个锚点只允许在 **1 m** 内吸附到当前方式的楼外道路，选择距原始位置最近的合格楼门。以现有楼外道路出发并标记 `startFromEntrance=true`。没有结果时返回 `NO_START_ROAD`。
3. 普通终点的吸附距离 **65 m**。步行到有门的终点用 **1 m**，要求接路点确实位于步行路段上。唐岛湾终点投影和门均应在建筑外。没有能吸附的目标返回 `NO_END_ROAD`。目标比较附加权重在普通终点为零，在步行门口为实际投影到楼门的距离，在骑行门口为 `(投影到接路锚点距离 + 锚点到门距离) * 3.6 / 1.35`，相当于按估算步行时间比较楼门。
4. 初始图用原有向边及其距离。添加一个合成起点、每个吸附目标的合成终点，以及比较全部目标的共同终端。对吸附边保持正向，合成起点接至有向边 `to`，合成终点从有向边 `from` 接入，距离至少 **0.1 m**。若吸附点距现有道路端节点不足 **0.1 m**，链接该端节点即可，连接无街段键。起终点位于同一无向街段且至少一个合法有向边上终点投影分数 ≥ 起点分数时，加合成起点直达合成终点的有向弧。合成终点以第 3 步的附加权重连共同终端。
5. 用 Dijkstra 最小堆按 `(cost,vertexIndex)` 优先，等价代价保留已有前驱，保留点、边与组的稳定顺序。到达共同终端的最短路径决定目标与楼门。不可达返回 `DISCONNECTED`。起点到目标投影以及实际步行门口（若有）的距离均小于 **5 m** 时返回 `TOO_CLOSE`。
6. 基准路线去掉共同终端和它的附加成本。备用路线仅对同一已选出口和同一吸附终点搜索。从最短路逆向追前驱所得的去重街段有序集合均匀抽取至多 **28** 个键（含首末，索引四舍五入）。逐个禁止一条无向街段的所有弧（含有该键的合成弧），分别重跑 Dijkstra。只留下图长度 ≤ 基准 **1.65 倍**、节点序列未重复的候选。按长度从短到长考察，与任何已保留线路的街段重叠率 `|交集| / min(|A|,|B|)` 超过 **0.90** 则跳过。两个空集合视为重叠 1，一个空集合视为 0。最终结果含基准最多 **3** 条，不硬凑。
7. 输出路线 ID 为 `route-1` 等。保留路线上的经纬度点，相邻距离小于 **0.05 m** 的点去重。步行到楼门时追加接路投影与门之间的短线，若间距小于 **0.05 m** 则直接替换最后一个点。骑行停在可骑行投影，提示用户步行至目的地。呈现的路线米数按最终折线重新求和，预计秒数为 `ceil(meters/modeSpeed)`。图上没有原始位置到道路的推测连线，骑行里程也不包含剩余步行部分。

路由计算应放进 Web Worker 或独立异步计算任务。原版取消上一任务并比较递增的规划代次，改变校区、方式、起终点或取消导航后，迟到结果不得覆盖新状态。

### 行进匹配和转向引导

对路线折线预先计算累积米数 `s[i]` 和段方位角。每帧 GPS 事件使用校正后的 `fix.accuracy`（米）、上一次匹配成功后的时间差 `dt`（秒）和上一次接受的沿线米数 `prev`。

```text
back = max(18, accuracy)
movement = clamp(dt, 0, 12) * modeSpeed * 1.6
forward = movement + max(18, accuracy * 1.25)
maxLateral = max(22, accuracy * 1.5)
for every segment intersecting [prev - back, prev + forward]:
    projection = projected point on segment
    along = s[i] + projection.fraction * (s[i+1] - s[i])
    reject when projection.distance > maxLateral or along outside the window
    progressPenalty = max(0, along - prev - movement - 8) * 0.25
    headingPenalty = 0 without reliable heading
    headingPenalty = min(abs(wrappedHeadingDifference), 90) / 90 * 2 otherwise
    score = projection.distance + progressPenalty + headingPenalty
choose the first candidate at minimum score
acceptedProgress = max(prev, chosen.along)
```

- 朝向惩罚最多相当于 **2 m**，只帮助区分邻近路段。单个 GPS 抖点不能把进度跳到很后面的折返并行道路。匹配失败不更新时间基准 `lastMatchedFix`。
- `positionAt(along)` 在累积长度序列二分找段，返回段下标和段内分数。将起点插值为当前位置，用于画出余下路线，禁止再拿未匹配的原始 GPS 切路线。
- 对每个内点从前后相距尽可能至少 **8 m** 的折线顶点取入出方位角，归一化差值到 `[-180,180)`。绝对角度小于 **25°** 忽略，**25°–35°**（不含 35°）为向左前方或右前方，**35°–155°**（不含 155°）为左转或右转，至少 **155°** 为掉头。差为负是左。两个转向间隔小于 **16 m** 时保留先提示，除非前一个是缓弯、后一个是强转，此时替换。
- 每次选第一个不早于 `along - 3 m` 的提示，下一提示距离超过 **120 m** 时显示沿当前道路直行，提示距离记 0。还剩米数为 `max(0, meters - along)`，还剩秒数为该距离除以速度向上取整。末尾提示通用目标为到达目的地附近，步行到门为到达目的地，骑行到门为步行前往目的地。到达通知在骑行门口情形明确停在骑行终点。

### 导航状态与浏览器定位适配

- `IDLE → PLANNING → READY` 或 `NO_ROUTE`。预览默认选第一条，`READY` 中可换路线。未选目的地、目的地仅参考、手选起点无路、缺可信位置分别有明确提示。手选起点只是预览。
- 点开始导航时若无精确近期位置，进入 `WAITING_LOCATION` 并待下一有效定位自动继续。若当前位置在校区外，不开始导航。仅在原预览来自实时位置且最新定位距原起点 **≤12 m** 时沿用选中的预览，否则从实时位置做 `REROUTING`。优先保持已选楼门，只有该门断路或无终点道路才比较其他入口。
- `NAVIGATING` 时按采样推进。定位过期、不精确或位置出校区时，保留已选路线及进度，暂停引导等待定位。路线从楼外开始、还没有匹配进度且定位仍在楼内时，显示请走到室外，保留跟随态。导航期间禁止切换出行模式。停止导航清空引导和进度，保留预览与选中项。
- 匹配失败先暂停引导并保留路线，尚未首次匹配时状态可继续保持 `NAVIGATING`。只有连续至少 **3** 个未匹配定位、首尾相隔至少 **4 s**、距上次重算至少 **15 s** 时重算。重算时若已经在跟随，保留旧折线及导航进度。若尚未在跟随，例如由手选预览首次开始，应清空旧预览线。成功后自动跟随新线，失败进入 `NAVIGATION_NO_ROUTE`，允许用有效新定位重试。没有既有跟随路线的失败支路可在距上次重算 **≥4 s** 且当前位置距失败规划起点 **≥max(15 m, accuracy)** 时自动再试。新匹配或失去可用定位会清掉偏航累计。
- 到达要求两次连续匹配均满足 **剩余 <14 m** 且 **原始位置距路线终点 <18 m**。进入 `ARRIVED` 并停止跟随。停止、换校区和改起终点都会失效取消旧任务。换校区保留当前定位与行进方式，清空旧路线和地点选择。
- Android 定位每 **1 s** 请求与检查，在界面处于前台 `RESUMED` 且用户开启定位时运行。精确模式用可用的 GPS、network、fused，近似模式仅 network、fused。首次无定位 **10 s** 标记无信号，失败注册每 **5 s** 重试。浏览器可用 Geolocation 前台监测适配，关闭或离开页面就清除监听。高精度请求只是请求，判断仍用实际结果。Web 时间戳需转成同一时钟基准应用年龄阈值。
- 可导航位置必须是精确授权，且 **0 < accuracy ≤30 m**、年龄 **0–15 s**。数据源丢弃未来或超过 15 s、越界坐标、非法精度。控制器另有 **30 s** 展示上限，原生合法样本通常已经受数据源 15 s 限制。保持最新位置，时间戳相同用精度更好的。较新位置精度半径比仍可用的旧点大 **≥8 m** 时，可以暂留近期旧点至旧点年龄超过 **4 s**。导航拒绝不递增的定位时间。
- Android 的行进朝向仅在速度 **≥1 m/s**、方位有效且方位精度 **0°–35°** 时进入匹配。浏览器不提供方位精度时可把匹配朝向保留为空，或明确记录额外设备约束，避免把手机指南针当作实际行进方向。

### 最小复现用例

构造坐标与路网小样验证算法，生产实地验收单列。以下复用 `CampusRoutingTest` 与 `CampusMapControllerTest`。可直接翻译同一用例及输入顺序。

| 用例 | 输入和判据 |
| --- | --- |
| 真实备用路 | A `[120,35]`、B `[120.0005,35]`、C `[120.001,35]`、D `[120.0005,35.0003]`，双向边 AB、BC、AD、DC。A→C 步行两条，先 A-B-C（91.0856 m，68 s），后 A-D-C（112.9058 m，84 s）。以 D、prev 46 m、accuracy 6 m 匹配第二条，垂距在 0.01 m 内，剩余在 1 m 与全长之间。 |
| 单行骑行 | 只有 A→C 允许步骑，C→A 仅步行。用 AC 的 20% 和 80% 两个内点作起终点。顺向可骑，反向骑行 `DISCONNECTED`，反向步行可通。 |
| 多门选择和骑行交接 | 路网用 A-B-C，某门为 `[120.001,35.00010]`、接至 C。步行结束于门，里程为 AC 加末段（102.2051 m，76 s），骑行结束于 C（91.0856 m，26 s）并提示步行。另一个双门用例把第一门的接路点放 AC 的 40% 处且门北偏 `0.00025°`，第二门接点在 60% 且门北偏 `0.00002°`，应选第二门。近门不连通时应只对另一可达门选路，备用也保持同门。 |
| 楼内出发与未接路 | A-B-C，建筑矩形为 `[120.0001,35.0002]` 至 `[120.0008,35.0009]`，初始位置和唯一宿主点都是 `[120.0004,35.00075]`，远门 `[120,35.00010]` 接 A，近门 `[120.0005,35.00015]` 接 B。实时步骑从 B 出发、里程为 BC（45.5428 m，步行 34 s 或骑行 13 s），原始室内点不入折线。手选室内点返回 `NO_START_ROAD`。复制相同轮廓或添加另一个可匹配主楼会让楼内起点不唯一，也返回错误。 |
| 并行道路抖点 | 折线 `[120,35] → [120.00033,35] → [120.00033,35.000072] → [120,35.000072]`，GPS `[120.000022,35.000045]`、prev=0、accuracy=5、dt=0。无朝向或 270° 均应匹配前段进度 <10 m、剩余 >50 m。 |
| 重算与续跟 | 手选 `[120,35]`，实时 `[120.0006,35]`，路口 `[120.0013,35]`，终点 `[120.002,35]`，偏航点 `[120.0013,35.00036]`。主线及路口到偏航点的边双向。点开始应以实时点为折线起点。10 s 后在 `[120.00075,35]` 进度应为约 13.6628 m。再过 45 s 到偏航点，随后每隔 2 s 发送一条，共三条，自动重算并从偏航位置继续导航。 |
| 引导与断点定位 | 向东起步约 6.4 m 后折向北，应从进度 0 提示约 10 m 以内左转。按样例 A-B-D 路线的第二段中点匹配后，`positionAt` 返回 `segmentIndex=1` 与 `fraction=0.5`，允许 `0.001` 误差。 |
| 定位新鲜度 | 精确定位精度 8 m、生成时刻 20 s，在 21 s 可用、36 s 不可用。改为近似权限或精度 85 m 时均不可导航。使用手选起点的预览点开始，精度 65 m 仍等待，之后到来的精度 5 m 的新采样应自动规划并导航。 |

建议以 **0.01 m** 或用例给定的数值误差核对位置与里程，用整秒核对 ETA 和精确枚举核对失败。道路朝向、门的室外位置与骑行限制只能在数据所覆盖的范围内校验。正式上线前仍需实地验收常用入口是否开放以及完整的跟随、偏航重算和到达行为。
